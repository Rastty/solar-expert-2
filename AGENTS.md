## Owner editorial quality standard — 2026-11-28

New articles must target a distinct Czech/Slovak buyer decision and avoid cannibalizing existing canonical pages. Prefer a substantive update to the existing URL when intent overlaps. Before publication, review actual SERP competitors and current GSC evidence when available; distinguish verified demand from hypotheses. Aim for the most useful complete answer, not arbitrary word count: direct opening answer, descriptive H2/H3 hierarchy, original worked examples and comparison tables, explicit assumptions and limits, current primary manufacturer/public sources for technical claims, relevant first-party calculators/quote paths, and genuinely useful FAQs. Write naturally in the target language, without keyword stuffing, fabricated experience, unverified price/stock or guaranteed savings. Use accurate SEO title/description, descriptive image alt text when relevant, accessible tables and crawlable links. Existing title/canonical and affiliate placements remain protected unless specifically authorized. Keep the approved new-post cadence, exact source lock and real production verification; report SEO or commercial improvement only after actual data. Owner prioritizes production work and fewer redundant tests; use existing checks rather than inventing additional gates.

### Visual publishing standard (owner 2026-11-28)

Design and structure are part of editorial quality, not an optional polish step. Use a concise answer-first opening, mobile-first visual hierarchy, meaningful comparison cards or accessible tables, a navigable contents list for longer articles, short scannable paragraphs, readable contrast and purposeful CTAs matched to the reader's decision. Avoid decorative clutter, excessive repeated buttons, inaccessible fixed-width layouts and generic stock illustrations. Keep article designs scoped to the article and use the established site visual language. Verify actual public output without redundant release checks; do not claim a visual/mobile browser inspection if only source HTML was checked.

### Selector UX standard (owner 2026-11-28)

Selection advisors must be understandable without prior technical expertise while preserving explicit electrical assumptions and all fail-closed compatibility checks. Use a short decision-first path: example or own inputs, clear units and contextual field hints, visually separated live computed requirements, then distinct valid matches and clearly labeled alternatives. Keep loading, invalid, error and empty states actionable and separate; never label a catalog gap as a technical impossibility or reduce safety margins to produce offers. Preserve native matcher and trusted event/affiliate contracts. Use mobile-first layouts, 44px or larger touch targets, responsive cards, keyboard focus, readable contrast and no horizontal overflow in the tool. Verify real interaction and layout in a representative mobile browser and desktop width with existing checks, not redundant test cycles. Do not claim perfect UX or measurable conversion uplift without actual user evidence.
